# A Ideia Central: Design é Projeto

Esta é provavelmente a conceituação mais importante para entender como construir um portfólio que realmente comunica valor.

## O que é Design?

A definição apresentada na aula parte da palavra _designare_ (latim), que significa **conceber/projetar algo** — e não simplesmente "desenhar".

> **Design = projeto + intenção + resolução de problema + comunicação**

Isso muda completamente a forma de pensar sobre um portfólio.

## O Erro Comum

Muito projeto é apresentado como:

> "Olha que tela bonita que eu fiz."

Ou no caso de desenvolvedores:

> "Aqui está meu código no GitHub."

## A Abordagem Correta

Em vez disso, o projeto deveria ser apresentado como:

> **"Eu tinha este problema → pensei nesta solução → tomei estas decisões → cheguei neste resultado."**

### Exemplo Prático

❌ **Forma incorreta:**

"Criei um app em Flutter com BLoC e Supabase"

✅ **Forma correta:**

"Um aplicativo de tarefas recebeu feedback sobre dificuldade para priorizar atividades. Implementei uma hierarquia visual clara com cores e ícones, uso de cards agrupados por categoria, e animações sutis para feedback de ação. Resultado: interface intuitiva que reduz carga cognitiva."

---

## Por que isso importa?

### Para Recrutadores

Quando você comunica dessa forma, você não está apenas mostrando que sabe programar. Você está mostrando que:

- ✅ Entende o problema antes de codificar
- ✅ Pensa em experiência de usuário
- ✅ Toma decisões intencionais
- ✅ Consegue explicar seu raciocínio
- ✅ Tem maturidade técnica

### Para o Portfólio

Isso transforma seu portfólio de:

```
"Sou um cara que programa"
```

em:

```
"Sou um desenvolvedor que sabe projetar soluções"
```

---

## Estrutura do Pensamento

Ao descrever seus projetos, sempre pergunte-se:

1. **Qual era o problema?**
2. **Por que era importante resolver?**
3. **Como você abordou a solução?**
4. **Quais foram suas decisões principais?**
5. **Como você mediu o sucesso?**

Essa narrativa é muito mais poderosa que simplesmente listar features ou tecnologias.

---

## Aplicação Imediata

Se você tem projetos no GitHub agora, comece a pensar em cada um deles através dessa lente:

- **Não:** "Flutter app com API REST"
- **Sim:** "Aplicativo que resolve X, implementado em Flutter, considerando Y e Z"

Essa mudança de perspectiva é o primeiro passo para um portfólio que realmente funciona.
